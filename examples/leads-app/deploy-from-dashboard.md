# ターミナルを使わずにデプロイする手順（Cloudflareの画面だけ）

PCにNode.jsもターミナルも用意せず、**ブラウザのCloudflare管理画面だけ**で公開する方法です。
コピペするのは `dist/worker.js`（アプリ全体を1ファイルにまとめたもの）と `schema.sql` の2つだけ。

> ⚠️ Cloudflareの画面の文言やボタンの位置は変わることがあります（この手順は2026年9月時点）。
> 違っていたら、その画面をスクショしてAIに貼り、「いまこの画面です。次はどこを押しますか」と聞いてください。

所要 15 分ほど。5つのステップです。

---

## ステップ1：データベース（D1）を作る

1. `https://dash.cloudflare.com` を開く
2. 左メニューの **Storage & Databases**（ストレージとデータベース）→ **D1 SQL Database** を開く
3. **Create**（作成）を押す
4. 名前に `leads-app-db` と入れて **Create** を押す

## ステップ2：テーブルを作る

1. いま作った `leads-app-db` を開く
2. **Console**（コンソール）タブを開く
3. `schema.sql` の中身を**まるごと貼り付け**て、実行ボタンを押す
4. 「Success」などの表示が出れば完了。**Tables** タブに `leads` が現れます

## ステップ3：アプリ（Worker）を作る

1. 左メニューの **Compute (Workers)** → **Workers & Pages** を開く
2. **Create**（作成）→ **Start with Hello World!** を選ぶ
3. 名前に `leads-app` と入れて **Deploy**（デプロイ）を押す

この時点で `https://leads-app.〇〇.workers.dev` が発行されます（中身はまだ Hello World です）。

## ステップ4：データベースをアプリにつなぐ

**先にこれをやります。** つないでいないとフォームの送信でエラーになります。

1. `leads-app` の **Settings**（設定）→ **Bindings**（バインディング）を開く
2. **Add**（追加）→ **D1 database** を選ぶ
3. 次のとおり入力する
   - **Variable name**（変数名）：`DB` ← **必ず大文字の DB**
   - **D1 database**：`leads-app-db`
4. 保存（**Deploy** / **Save**）を押す

## ステップ5：コードを貼り付ける

1. `leads-app` の画面で **Edit code**（コードを編集／`</>` のアイコン）を開く
2. エディタに出ている Hello World のコードを**全部消す**
   （`Ctrl + A`／Macは `⌘ + A` で全選択 → Delete）
3. `dist/worker.js` の中身を**まるごと貼り付ける**
4. **Deploy**（デプロイ）を押す

`https://leads-app.〇〇.workers.dev` を開くと、申し込みフォームが表示されます。

## ステップ6：管理画面の合言葉を設定する

1. `leads-app` の **Settings** → **Variables and Secrets**（変数とシークレット）を開く
2. **Add**（追加）を押して、次のとおり入力する
   - **Type**（種類）：**Secret**（シークレット）← Text ではなく Secret を選ぶ
   - **Name**（名前）：`ADMIN_PASSWORD`
   - **Value**（値）：あなたの決めた合言葉（誕生日や使い回しのパスワードは避ける）
3. 保存（**Deploy** / **Save**）を押す

> 合言葉を設定するまで、`/admin` は「未設定です」と表示するだけで**中身を一切出しません**。
> 途中で放置しても情報は漏れないので、あわてなくて大丈夫です。

---

## 動いたかどうかの確かめ方

1. `https://leads-app.〇〇.workers.dev/` を開いて、自分の名前とメールで申し込んでみる
2. `https://leads-app.〇〇.workers.dev/admin` を開く
   → ユーザー名は**空欄でOK**、合言葉を入れる
3. いま送った内容が一覧の**先頭**に出ていればOK
4. 対応状況を「連絡済み」に変えて、**ページを再読み込みしても「連絡済み」のまま**なら保存できています
5. 最後に**シークレットウィンドウ**で `/admin` を開き、合言葉なしでは中身が見えないことを確認する

---

## つまずいたら

| 症状 | どうするか |
| --- | --- |
| フォームは出るが、送信すると「保存に失敗しました」 | ステップ4のバインディングを見直す。変数名が `DB`（大文字）になっているか |
| `/admin` に「ADMIN_PASSWORD が未設定です」と出る | ステップ6がまだ。種類が **Secret** になっているかも確認する |
| `/admin` が合言葉なしで開けてしまう | いちばん危ない状態です。すぐAIに相談してください（そうならない作りですが、必ずシークレットウィンドウで確認を） |
| 合言葉を忘れた | ステップ6で同じ名前 `ADMIN_PASSWORD` を上書きすれば変えられます（復元はできません） |
| 画面が手順と違う | スクショをAIに貼って「いまこの画面です。次はどこを押しますか」と聞く |

---

## あとから中身を直したくなったら

このやり方は「1ファイルを貼る」方式なので、直すときも同じです。
`src/` を直したあと、次のコマンドで `dist/worker.js` を作り直して、ステップ5をやり直します。

```bash
npm run build
```

（このコマンドを打てない場合は、AIに「src を直して dist/worker.js を作り直して」と頼んでください）

ターミナルが使える環境なら、`./deploy.sh` のほうが速いです。README を参照してください。
